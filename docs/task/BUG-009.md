# BUG-009 — Entry scroll lands a few turns above the latest

## Symptom (user)

Opening a session's chat lands the scroll a few turns above the latest message
instead of at the bottom.

## Root cause (user's hypothesis — confirmed)

`useIsMobile()` initialized to `false` and flipped to `true` only in a post-mount
effect. On a phone the composer therefore rendered in its **expanded desktop
style on the first frame** (`mobileCollapsed = isMobile && …` = false), then
**collapsed to 52px once isMobile flipped** — a height change AFTER the initial
scroll-to-bottom, which shifted the bottom so entry landed short. The "two
composer styles" the user pointed at.

Secondary: async content (Shiki code blocks, markdown, images) can also grow the
list after the first pin.

## Fix

- **Root:** `use-mobile.ts` initializes `isMobile` **synchronously** from
  matchMedia on the first render (bkd is a pure client SPA — no SSR). No more
  desktop→mobile flip → composer renders in the correct style from frame one →
  no post-mount height shift.
- **Safety net:** ChatBody's entry restore re-pins to bottom across a short
  settle window (60/180/360/600ms), aborting if the user has scrolled away
  (gap > 600px) — absorbs async content growth too.

## Verification

lint + tsc + 404 tests; on-device verify entry lands on the latest message.
