# BUG-014 — Thinking block renders below assistant response when reasoning arrives late

## Symptom

The user reports that the thinking/reasoning block is shown **under** the
assistant response instead of above it.

## Root cause

The backend `TimelineConverter` assigns `sequence` based on the timestamp of the
chunk that opens a segment. Some engines (OpenCode/ACP) emit the assistant
response before the reasoning/thinking update. When that happens, the thinking
segment gets a larger `sequence` than the assistant segment, so `toTimeline()`
sorts the assistant before the thinking. `useAcpTimeline` then sees the
assistant first (with no pending thinking) and emits a standalone `thinking`
item after it, which the UI renders below the response.

## Fix

Post-process the built timeline items so a standalone `thinking` item that
immediately follows an `assistant-message` entry in the same turn is folded into
that assistant entry's `thinking` property. The UI already renders attached
thinking above the assistant content.

## Verification

- Added unit test for `assistant-message` followed by `thinking` in the same turn.
- Existing `useAcpTimeline` tests continue to pass.
