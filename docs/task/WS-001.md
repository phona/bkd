# WS-001 — Multi-project association (see PLAN-037)

Associate other bkd projects when creating an issue/session; create a worktree on
the SAME branch in each linked project's repo (borrowed from AoE). Design in
PLAN-037.

## P1 (backend) — done

- Schema: new `issue_projects` link table (`issueId`, `projectId`, `isPrimary`,
  commonFields; unique `(issueId, projectId)` + `issueId` index). Migration
  `drizzle/0031_yielding_pepper_potts.sql` (drizzle-generated).
- `create.ts`: accepts `linkedProjectIds?` (openapi `CreateIssueSchema` + shared
  type). Validates each (exists, not soft-deleted, not archived, not the primary;
  deduped); writes one primary row + one per linked project inside the create tx.
- Worktree materialization: `materializeLinkedWorktrees(issueId, branch, onError)`
  + `buildLinkedReposPromptSuffix` in `utils/worktree.ts`, wired into
  `orchestration/execute.ts`. Each linked repo gets a worktree on the SAME branch
  (own base + fetch). Partial-failure tolerant: a failing repo emits a
  chat-visible diagnostic and is skipped; the primary execute always proceeds.
  Successful linked paths are injected into the agent prompt; agent cwd stays the
  primary worktree.
- Query API: `GET /api/projects/:projectId/issues/:id/linked` returns
  `[{ projectId, name, directory, worktreePath, isPrimary }]`. Shared type
  `LinkedIssueProject`; client `kanbanApi.getIssueLinkedProjects`; hook stub
  `useIssueLinkedProjects` (P2 will consume).
- Tests: `test/issue-linked-projects.test.ts` (link rows + validation + `/linked`
  + multi-repo same-branch materialization with partial failure).

## Deferred

- P2 (frontend): CreateIssueDialog project linker, dock-rail/mobile repo switcher,
  card/detail "N repos" surfacing, i18n.
- P3: merge-back + delete iterate all linked repos.
