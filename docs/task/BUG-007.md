# BUG-007 — Final chat response missing until refresh (settle race)

## Symptom

A turn finishes: status flips to review (settle/done fires), but the final
assistant message isn't rendered live — the user must refresh to see it.

## Root cause

The final, merged assistant content is a **`dbOnly` snapshot**: `timeline-emit.ts`
deliberately skips `dbOnly` entries from the SSE `timeline-entry` channel
(line ~37), so the live view only ever has the streaming chunks. The full merged
content is delivered to the client by `onDone`'s `/logs` reconciliation refetch.
But `emitIssueSettled` (`done`) can fire **before** that `dbOnly` row is committed
to the DB, so the first refetch reads stale data and misses the tail — a manual
refresh seconds later succeeds because the write has landed by then.

## Fix

- **Mitigation (this change, low-risk, frontend):** after `onDone`, run two
  staggered reconcile refetches (350ms + 1200ms) so a write-that-lands-just-after
  `done` is still picked up without a manual refresh. Timers cleared on unsub.
- **Root fix (PLAN-032):** make settle await the final persist before emitting
  `done`, and/or deliver the final merged content over SSE so no refetch race
  exists. Tracked in the chat single-source-of-truth work.

## Verification

lint + tsc + use-issue-stream tests; live verify on deploy (no manual refresh
needed after a turn settles).
