# BUG-005 — Chat scroll lands at wrong position when switching sessions

## Symptom

Switching to a session: the history (1) lands at a wrong position and (2) does not
land at the latest message.

## Root cause

Per-issue scroll restore stores an **absolute pixel `scrollTop`** (ChatBody scroll
handler ~363) and writes it back on switch (ChatBody `useLayoutEffect` ~398). Content
height changes after the restore — async Shiki/markdown/diff rendering grows height,
and new messages may have arrived while away — so the absolute px points at the wrong
message (symptom 1) and is no longer at the bottom (symptom 2).

## Fix (hybrid — land latest when following, resume when reading)

Replace the pixel anchor with a semantic anchor:
- Save `{ atBottom, anchorId }` per issue: `atBottom` = near bottom; `anchorId` =
  top-visible messageId when not at bottom.
- Restore (once per issue): `atBottom`/no-anchor → land at the latest message (rely on
  the bottom-anchor + async settle that already exist); else scroll the `anchorId`
  message into view (height/virtualization-safe), reusing the existing jump path.
- Migration: legacy numeric localStorage entries → treat as no-anchor → land latest,
  so stale pixels never mis-position again.

## Verification

- Unit-test the restore-decision + anchor-capture pure logic (jsdom has no layout).
- Manual: desktop 1280 + mobile 375 — follow then switch back → latest; read history
  then switch back → same message; session with code blocks → no drift.
