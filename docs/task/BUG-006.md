# BUG-006 — Terminal won't open: launcher Bun.serve has no websocket handler

## Symptom

Opening a terminal fails. The PTY session is created (`terminal_session_created`)
but the WS upgrade for `/api/terminal/ws/<id>` throws and the session is reaped:

```
TypeError: To enable websocket support, set the "websocket" object in Bun.serve({})
  at upgradeWebSocket ... path: /api/terminal/ws/<id>
```

Affects ALL WebSocket endpoints (terminal, etc.), not just BUG-004's leak.

## Root cause

Since 0.0.173 the **launcher** owns the long-lived `Bun.serve` (graceful upgrade);
the app bundle only exports `createApp`/`createCore`. Hono's `upgradeWebSocket`
(`hono/bun`) requires `Bun.serve({ websocket })`. The launcher's `Bun.serve`
(`scripts/launcher.ts`) never set `websocket`, and the bundle didn't export it —
so every WS upgrade failed. (`apps/api/src/index.ts`, the non-launcher entry,
does pass `websocket`, which is why dev/full-compile worked.)

## Fix

- `app-entry.ts`: `export { websocket } from 'hono/bun'` so the launcher gets the
  bundle's own Bun WS handler (same module graph as the routes' upgradeWebSocket).
- `scripts/launcher.ts`: `Bun.serve({ websocket: bundleMod.websocket, ... })`.

Requires a **new launcher binary** (compile --mode launcher) AND a new bundle.

## Verification

tsc + lint; after deploy, open a terminal and confirm WS attaches (no
`unhandled_error` / `terminal_unattached_reaped` for the WS path).
