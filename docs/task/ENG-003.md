# ENG-003 Engine rendering adapter layer

- **status**: in_progress
- **priority**: P2
- **owner**: claude
- **createdAt**: 2026-05-10 07:00

## Description

BKD already has a clean adapter layer for the **execution side** of each
engine: `EngineExecutor` (with `engineType`, `protocol`, `capabilities`,
`spawn`, `normalizeLog`, ...) lives at `apps/api/src/engines/types.ts`,
each engine owns a directory under `apps/api/src/engines/executors/`,
and ACP engines have a sub-agent registry (`acp/agents/`).

There is **no equivalent adapter layer for the rendering side**. As a
result, engine-specific UI behaviour ends up hardcoded at call sites in
the frontend:

- `SessionMessages.tsx` — `if (engineType?.startsWith('acp'))` selects
  the timeline component (raw acp string-prefix check).
- `ChatInput.tsx` / `CreateIssueDialog.tsx` — `isClaudeEngine` hardcoded
  engine list controls model-lock behaviour.
- `lib/assistant-preamble.ts` — opencode-specific header list used to
  detect the task-tracking preamble that opencode bundles into every
  assistant message. Currently runs on every engine; relies on a
  2-section guard to avoid false positives.

When a new engine ships, every such call site has to be touched. The
existing `capabilities: EngineCapability[]` field on `EngineExecutor`
holds engine features (session-fork, plan-mode, ...), not rendering
hints — extending it would mix two semantics.

This task adds a small, additive adapter layer that lets each engine
(and ACP sub-agent) declare rendering-relevant hints, and migrates
the frontend hardcoded checks to query those hints.

Acceptance criteria:

1. A new `RenderingHint` type exists in shared types covering at
   minimum `task-plan-preamble`, `inline-thinking`,
   `lock-model-when-omitted`.
2. The backend exposes per-issue rendering hints via the `Issue`
   API response (`Issue.renderingHints`).
3. Frontend `splitAssistantPreamble` is gated by the hint so only
   opt-in engines (currently opencode) get the split behaviour.
4. The existing `isClaudeEngine` hardcoded check migrates to the
   `lock-model-when-omitted` hint.
5. `SessionMessages.tsx`'s `startsWith('acp')` is intentionally NOT
   migrated (structural pipeline switch, orthogonal to behaviour hints).
6. Tests cover both "hint enabled" and "hint disabled" paths.

## Notes

Triggered by user observation that `splitAssistantPreamble` was hardcoded
to opencode header strings. The 2-section guard makes this safe in
practice, but the deeper concern is that BKD already has an adapter
layer (`EngineExecutor.capabilities`) and the rendering layer was never
plugged into it.

See PLAN-007 for the proposed shape.
