# WT-001 Allow choosing worktree base branch and custom branch name

- **status**: completed
- **priority**: P1
- **owner**: claude (pma)
- **createdAt**: 2026-06-06 13:48

## Description

Worktrees are always cut from one auto-resolved branch with a fixed name, so
users cannot base work on a different branch or name it themselves.

Current state:
- Branch name hardcoded `bkd/${issueId}`
  (`apps/api/src/engines/issue/utils/worktree.ts:99`).
- Start point auto-resolved (origin/HEAD → main → master → release → develop …)
  in `resolveStartPoint()`; `execute.ts:75` calls `createWorktree(...)` and
  **never** passes the optional `startPointRef` the function already supports
  (the fork-dependent flow does pass it — `services/fork-dependent.ts:96`).
- `executeIssueSchema` (`routes/issues/_shared.ts:77`) has no branch field.

Goal: let users optionally pick a base branch and/or a custom branch name when
running an issue, while keeping the zero-config default (current behavior) for
newcomers.

Acceptance criteria:
- Backend: `executeIssueSchema` accepts optional `baseBranch?` and `branchName?`,
  threaded into `createWorktree`.
- Frontend: a collapsed "advanced" section in the create/execute flow — base
  branch picker (from `/api/git` branches) + optional branch name (blank =
  current `bkd/{id}` default). No git jargon forced on new users.
- Mobile + desktop parity for the new controls.
- Leaving advanced options untouched reproduces today's behavior exactly.
