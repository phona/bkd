# BUG-011 — Entry lands on a stale anchor

## Symptom (user)

Entering a session jumps to some mid-conversation position (a previous message,
e.g. #61) that is neither the latest message nor the user's real last-read spot.

## Root cause

The ChatBody restore effect had a "resume reading position" branch (BUG-005):
`savedAnchor && !savedAnchor.atBottom → scrollIntoView(anchorId); return`. The
saved anchor was unreliable — entry-time async growth and re-pin scrolls polluted
the saved position — so it restored to a stale/wrong anchor and skipped the
land-at-bottom path entirely.

## Fix

Drop the resume-reading-position branch. Entering a session ALWAYS lands on the
latest message (predictable). Kept + extended the BUG-009 re-pin settle window
(60/180/360/600/1000/1600ms; abort if user scrolled away >600px) to absorb async
content growth on long conversations. Supersedes BUG-005's resume feature.

## Verification

lint + tsc + 404 tests; on-device verify entry always lands on the latest message.
