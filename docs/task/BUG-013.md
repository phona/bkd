# BUG-013 — OpenCode ACP model discovery fails in BKD project directory

## Symptom

`/api/engines/probe` returns an empty `acp:opencode` models array even though
OpenCode is installed and `opencode --version` works. The engine availability
probe marks `acp:opencode` as installed, but no models are discovered.

## Root cause

OpenCode's ACP `session/new` implementation has a project-directory service bug
(see anomalyco/opencode#31091). When the ACP child process is spawned in
`/mnt/d/Projects/bkd` and the session `cwd` is also the project directory,
`session/new` returns `-32603 Internal error: OpenCode service failure` with
`service: "directory"`. Model discovery runs exactly this code path, so the
model query errors silently and returns no models.

## Fix

For ACP model discovery only, spawn the agent in a neutral working directory
(e.g., `/tmp`) and use the same neutral directory as the session `cwd`. The
model list is agent-global, so the project directory is irrelevant here. The
execution path continues to use the real project directory for the session.

## Verification

- `/api/engines/probe` returns `acp:opencode` models.
- Other ACP agents (`acp:gemini`, `acp:codex`, `acp:claude`) continue to return
  models.
